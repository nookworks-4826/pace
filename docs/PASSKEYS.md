# パスキーでPaceを開く

v1.2.0から、パスキーを登録してアプリのロックを解除できます。Galaxyの指紋認証、iPhoneのFace ID・Touch IDなど、端末が提示する本人確認方法を使います。端末のPIN・パスコードが表示される場合もあります。

## 登録する

1. いつものPaceで「設定 → アプリの更新」を開き、現在のバージョンが1.2.0以降であることを確認します。古い場合は「更新を確認 → 更新を適用」を押します。
2. 「設定 → アプリロック → パスキー」を選びます。
3. すでにPINやデバイス認証を設定している場合は「現在のロックで確認」を押し、本人確認をします。
4. 「パスキーを登録」を押します。端末が表示する保存先と本人確認の案内に従ってください。
5. 「現在：パスキー」に変わったら「認証を試す」を押します。
6. アプリを開き直し、「パスキーで解除」で開けることを確認します。

登録をキャンセルしたり保存に失敗した場合、以前のロックを保ちます。「変更をやめる」で設定を閉じられます。保存可否は登録時に端末・ブラウザ・認証プロバイダーが確認します。

## 端末側の準備

- **Galaxy**：端末の設定で画面ロックと指紋を登録します。普段使うChromeなどの対応ブラウザで、公開済みのHTTPS URLを開いてください。パスキーの保存先は端末が提示するものを選びます。
- **iPhone**：設定でパスコードとFace IDまたはTouch IDを設定し、「パスワード」などのパスキー保存先を有効にします。普段使うSafariまたはホーム画面のPaceから登録してください。

設定名はOS・機種・保存先により異なります。アプリロックの「ヘルプ」内でも確認できます。指紋・顔の画像をPaceが取得することはありません。

参考：[Google公式の対応環境](https://developers.google.com/identity/passkeys/supported-environments)、[Apple公式のパスキー案内](https://developer.apple.com/passkeys/)。この開発環境で確認したのはChromeの仮想認証器です。実際のGalaxy・iPhone、Samsung Pass、Googleパスワードマネージャー、Appleのパスワードアプリの操作・同期・オフライン認証は実機での確認が必要です。

## 家計データとロックの関係

- パスキーはこのブラウザのPaceを開く鍵です。アカウント作成やサーバーへのログインはありません。
- 保存先の設定によってパスキーが同期されることがあります。家計データは同期されず、別の端末にはバックアップを復元してからロックを登録し直します。
- 登録済みの公開鍵だけを受け入れます。新しいブラウザで同期済みの鍵を選ぶだけで、元の端末の記録を取得する機能はありません。
- 既存のデバイス認証はそのまま使えます。自動的にパスキーへ変換しません。
- ロックはPIN・デバイス認証・パスキーのいずれか1つです。端末のPIN・パスコードは、Pace独自の6桁PINとは別です。
- この機能は画面ロックで、IndexedDB自体の暗号化ではありません。家計のバックアップは別途暗号化できます。
- ロック設定はPaceのバックアップに含まれません。公開URL・ブラウザを変更したりバックアップから復元した場合は改めて登録します。
- Paceのロックを変えても保存先のパスキーは自動削除されません。使っている鍵を先に削除すると解除できなくなるため、変更後に新しい方法で解除できることを確認してください。

## 実装と互換性

WebAuthnの`authenticatorAttachment: platform`、`residentKey: required`、`requireResidentKey: true`、`userVerification: required`で登録します。`credProps`が明示的に非residentを返した場合は以前のロックを変更せずエラーにします。省略された場合は必須resident keyの指定に従います。

challenge・origin・RP ID・本人確認フラグ・ES256公開鍵・署名の検証は従来の処理を共有します。生体情報や秘密鍵は保存しません。変更前の本人確認と新規登録はボタン操作を分け、本人確認の有効期限を1分とし、途中でロック設定が変わった場合も再確認します。

認証用の`pace:local-lock:v1`の形式を維持します。`pace:passkey-label:v1`は登録したcredential IDに対応する表示専用情報で、消失しても認証の可否は変わりません。DB名`pace`・Dexie v2・バックアップschemaVersion 1を維持し、財務計算や記録の構造は変更していません。

## 開発時の検証

```powershell
npm run test
npm run build
npm run preview
```

別のPowerShellで、プレビュー先を指定して実行します。PlaywrightのChromiumが未導入なら事前に`npx playwright install chromium`を実行します。

```powershell
$env:PACE_QA_BASE_URL = 'http://localhost:4173/'
$env:PACE_QA_OFFLINE = '1'
npm run test:passkeys
```

一時ブラウザと仮想CTAP2認証器で、PINからの切り替え・登録キャンセル・resident key保存・再起動後の解除・オフライン解除・非対応時のPIN利用を確認します。普段利用するブラウザや実際の記録は使用しません。
