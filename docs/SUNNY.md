# Pace 1.3.0

## 日々の操作

- イエローのアイコン、白い画面、青い決定ボタン。サニー・スカイ・ミント・ニュートラルの4配色を選べます。テーマの内部IDは以前と同じです。
- ホームの「今使っていい金額」を大きく表示し、持っているお金のうち、使える分と予定・未払い分をバーで確認できます。カードを押すと内訳を開きます。
- 「これ、買ったら？」を押し、金額を入力すると購入後の残額と明日からの1日あたりの目安を表示します。支出は追加されません。
- 初回の案内に短く動く図、金額の変化や保存完了に短い動きを追加しました。常時動くキャラクターや連続利用を強いる演出はありません。OSの「動きを減らす」に従います。
- 新規設定はライト表示。既存のダーク・システム設定は保持します。ホーム右上の太陽ボタンでライトへ切り替えられます。

## 試算の範囲

試算は、新たに通常の買い物をした場合の計算です。現在の使える金額から購入額を引き、月予算があればその残額からも引きます。明日からの目安は、その2つの小さい方（下限0円）を明日から月末までの日数で割ります。月末は翌日以降の目安を表示しません。

すでに確保した固定費・カード引落・返済・貯金移動には使いません。未入力の残高は推定せず、未登録の支払いや未入金の収入を加味しません。試算によって支払能力を保証する機能ではありません。

## 端末内の学習

店名の分類候補には、既存のキーワード・修正履歴・類似店名の判定に加え、文字の組み合わせから共通パターンを探す小さな統計分類器（TF-IDFとカテゴリ代表ベクトル）を使用します。生成AIや会話モデルではありません。

記録済みの異なる店名が6件以上、カテゴリーが2種類以上ある場合に限り、1分類に複数店舗からの根拠があり、既知の文字パターンが十分含まれる場合だけ判定します。根拠が弱い・判断が割れるときは推測を控えます。表示は「記録からの候補」とし、修正してから保存できます。候補だけで支出を自動保存しません。

過去に本人が同じ店名へ指定した分類を優先します。削除済み・アーカイブ済みカテゴリーを新たな候補にしません。最新600店名までを使い、モデルのダウンロード、外部API、APIキー、追加の利用料金は必要ありません。家計データの新たな送信先や分析SDKは追加していません。

モバイルで毎日使うため、今回は大容量の生成AIを追加していません。検討時点のChrome組み込みAIには端末要件とモバイルの制約があり、WebGPUモデルにも対応状況とダウンロードの負担があります。[Chrome公式要件](https://developer.chrome.com/docs/ai/get-started)、[Transformers.jsのWebGPU案内](https://huggingface.co/docs/transformers.js/guides/webgpu)。採用した分類器はスマホのJavaScriptだけでオフライン動作します。

## 更新とアイコン

アプリURL、IndexedDBのバージョン、バックアップ形式、パスキーの保存形式は変更していません。同じ公開先へ更新し、設定の「アプリの更新」から適用します。ホーム画面アイコンが更新される時期はOS・ブラウザによって異なります。アイコンだけ古い場合も、サイトデータを削除する必要はありません。

公開用アイコンは `public/icon.svg` から `npm run icons` で再生成できます。PNGファイル名を変更して新旧のキャッシュを区別し、古いファイルも旧クライアント向けに残しています。

## 再現する検証

単体テストは `npm test`、ビルドは `npm run build`。Vite起動後、`PACE_QA_BASE_URL` にそのURLを指定して `npm run test:refresh` を実行します。試算の前後で全DBストアが一致すること、分類候補の保存、文字のコントラスト、表示設定、動きを減らす設定を確認します。

本番ビルドを配信したURLを指定して `npm run test:offline`、localhostのURLで `npm run test:passkeys` を実行できます。`PACE_QA_OFFLINE=1` でパスキーのオフライン確認も行います。Chromeの場所を指定する場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE` を設定します。

`PACE_QA_PREVIOUS_DIST` に旧本番ビルドのフォルダーを指定して `npm run test:update` を実行すると、実際にService Workerを入れ替えます。旧版がv1.2.0以降なら `PACE_QA_UPDATE_PASSKEY=1` で旧版に登録したパスキーの引き継ぎも確認できます。仮想認証器による試験であり、GalaxyやiPhone実機での認証動作を証明するものではありません。
