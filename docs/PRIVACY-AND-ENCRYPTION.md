# Pace 2.0 の保存・暗号化・通信

> Pace 2.1.1では銀行の有料自動連携を採用せず、アプリからMoneytreeの認可・金融APIへ接続する入口と起動時の同期処理を外しました。残高は本人が登録し、カード明細は本人が選ぶCSVで取り込みます。旧版のデータ形式・暗号化・バックアップとの互換性は維持しています。以下の金融連携の説明は、2.0の試作コードについての技術記録です。

この文書は 2.0 の実装を対象にしています。1.x の検証記録にある「IndexedDB 自体は暗号化していない」という説明は、当時の版についてのものです。

## 保管庫

初回起動時、12〜1,024文字のパスフレーズで端末内の保管庫を設定します。旧版の記録がある場合は、既存の画面ロックを確認してから移行します。暗号化前に記録を消したり、初期データで上書きしたりする処理はありません。

IndexedDB の DB 名は `pace`、Dexie のスキーマは v3 です。公開設定を保存する `vaultMeta` を除き、全28ストアの各レコードを Web Crypto の AES-256-GCM で暗号化します。支出・収入・口座・金融明細・給与判定ルール・同期状態・レシート画像・入力下書き・金融認証情報も対象です。書き込みごとにランダムな12バイトの IV を使います。データの認証にはテーブル名と暗号化した主キーも含め、別の行への差し替えを拒否します。検索用の主キー・副索引は別の鍵による HMAC-SHA-256 で置き換え、復号後には索引と本文の対応も検証します。

パスフレーズとランダムな16バイトの salt から PBKDF2-HMAC-SHA-256 を600,000回実行し、独立した暗号鍵と索引鍵を導出します。取り出し不可の `CryptoKey` として使用し、パスフレーズや鍵は永続保存しません。ロックすると鍵と索引用メモリーキャッシュを破棄します。`vaultMeta` に残るのは KDF の種類・回数・salt・暗号化した確認用文字列など、復号に必要な公開パラメーターです。使用 API は [Web Crypto の仕様](https://www.w3.org/TR/webcrypto/)に従います。回数は [OWASP の PBKDF2-HMAC-SHA-256 推奨値](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)を参考にしています。Pace が暗号製品の認証を取得したという意味ではありません。

移行は全ストアを1つの書き込みトランザクションで処理します。暗号化した各レコードを復号して旧記録と照合できた場合だけ、暗号化の設定を確定します。処理中の失敗は全体を巻き戻し、旧記録を残します。既存の暗号文があるのに設定が失われている場合は、再初期化して上書きせず停止します。

PIN・Galaxy の指紋認証・iPhone の端末認証・パスキーは、従来の画面ロックとして別に働きます。これらから保管庫の暗号鍵を取り出したり、パスフレーズを自動再生成したりする機能はありません。画面ロック用の公開鍵・credential ID・PIN 検証用の派生値などだけを、従来の2種類の `localStorage` キーに保存します。家計記録・金融トークン・パスフレーズは保存しません。

## どの通信が起きるか

| 操作               | 送信するもの・保存するもの                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| アプリの起動・更新 | 配信元からアプリの静的ファイルを取得します。家計データを GitHub へ送信する機能はありません。                                                     |
| 手動で家計を記録   | この端末の暗号化した IndexedDB に保存します。外部の家計サーバー・広告・アクセス解析へ送信しません。                                              |
| レシート読み取り   | 同じ配信元から日本語・英語 OCR のモデルと処理コードを初回取得し、画像を端末内で処理します。画像や認識した文字を外部 AI に送信しません。          |
| レシート画像を保存 | 本人が保存のチェックを入れ、支出の保存を確定したときだけ、再エンコードした画像を保管庫へ保存します。元の写真の EXIF 位置情報は保持しません。     |
| 金融機関と連携     | 本人の同意と正式な Public Client 設定がある場合に限り、Moneytree の認可・金融 API と通信します。未設定時に実連携を成功扱いすることはありません。 |
| リマインダー       | 一般的な「今日のPaceを確認してください」という内容だけを使います。通知やカレンダーに残高・取引・トークン・鍵を入れません。                       |

Moneytree の認可は Authorization Code + PKCE S256 を使用します。銀行の ID やパスワード、`client_secret` をアプリ内に入力・埋め込みする構成ではありません。`access_token`・`refresh_token`・認可処理中の PKCE verifier は、保管庫内の専用ストアに暗号化して保存します。認可から戻った URL の code・state などは、起動時に履歴から取り除いてメモリーだけで処理します。

金融 API へのトークン送信先は固定の公式ホストと `/link/` 配下に制限します。通信は `cache: no-store`、`credentials: omit`、`redirect: error`、`referrerPolicy: no-referrer` を指定します。API 応答・画像・金融認証情報を Service Worker や CacheStorage に保存する実装はありません。Service Worker のキャッシュ対象は、アプリの静的ファイルと同一配信元の限定した OCR ファイルです。OCR エンジン独自の永続キャッシュも無効にしています。アプリの実行コードに金融情報や例外の本文を console へ出力する処理はありません。

## バックアップと復元

2.0 はバックアップ `schemaVersion: 2` を出力し、従来の `schemaVersion: 1` も読み込めます。復元前に金額・ID・関連付け・画像形式などを検証し、端末の家計データ全体を1つのトランザクションで置き換えます。途中で失敗した場合は元の記録を残します。

金融トークン、PKCE verifier、画面ロックの設定、保管庫の鍵はバックアップに含めません。復元先ではその端末の保管庫を使用し、金融連携は未接続に戻します。再認可するまで同期しません。レシート画像は、本人が保存したものだけ家計データとしてバックアップに含まれます。

復元・全データ削除を始める前に、進行中の金融処理とメモリー上の口座キャッシュを無効にします。金融認証情報の書き込みと置き換えは Web Locks で直列化し、認可ごとのセッション番号を照合します。別タブから遅れて届いたトークンや口座情報で、削除した連携を復活させません。全データ削除後も保管庫の暗号化設定は維持し、同じパスフレーズを使用します。

通常の JSON・CSV・Excel は本人が選んで作成する平文ファイルです。保管庫の暗号化が、ダウンロード済みの平文ファイルを暗号化するわけではありません。暗号化バックアップ `.pacebackup` は別のパスワードと salt・IV による AES-256-GCM を使用します。2.0 の新規出力は PBKDF2-HMAC-SHA-256 600,000回で、旧310,000回のファイルも復号できます。保管庫とバックアップのパスワードは別設定です。

パスフレーズや暗号化バックアップのパスワードを失った場合、Pace に復号のための回復キーはありません。端末・ブラウザーの保存領域の消去、OS の故障、URL の変更に備えるには、本人が使えるバックアップが必要です。URL が変わった場合はブラウザーの保存領域も別になるため、旧URLのデータを自動的に引き継ぎません。

## 保護の範囲と検証

保管庫は、ロック中のアプリの保存内容を平文で読まれにくくする保管時暗号化です。レコード数、ストア名、暗号文のサイズ、同じ索引値の繰り返しは観測できます。短く推測しやすいパスフレーズの総当たり、すでに解除された端末、同じ配信元の改ざんされたアプリコード、OS や拡張機能による侵害を防ぎきる機能ではありません。移行後も、OS バックアップや過去のブラウザープロファイルに存在した旧平文の完全消去を保証する処理はありません。

```powershell
npm run privacy:audit
```

このコマンドは実際の利用者のブラウザープロファイルを開きません。ソース内の禁止された保存・ログ・通信パターンを確認した後、架空のデータだけを使う使い捨ての fake IndexedDB で次を実行します。

- 全29ストアを下層の IndexedDB API で読み、公開パラメーター以外が暗号化され、索引・口座名・トークン・給与メモ・下書き・レシート画像が平文で残らないことを確認。
- 旧記録の原子的移行、復号後の一致、注入した暗号化失敗での巻き戻しを確認。
- 書き込みごとの IV 更新、別タブの平文書き込み拒否、ロック時の鍵破棄、誤パスフレーズで記録が変わらないことを確認。
- 旧バックアップ互換、新バックアップの全記録、認証情報の除外、暗号化ファイルの復元を確認。
- mock/manual と未設定の Moneytree が外部通信や認証情報の保存を行わないことを確認。

結果は `test-results/privacy-audit.json` に出力します。追加の `src/tests/vault.test.ts` は実旧v2スキーマからのアップグレード、移行時の復号検証失敗、暗号文・副索引改ざんの拒否、CRUD・一意索引・liveQuery を検証します。ソース検査はパターン検査で、完全なデータフロー解析や侵入試験ではありません。iPhone・Galaxy の保存領域復旧や生体センサー自体の保証にもなりません。
