# Pace 2.2.1 更新・移行・復旧

この版は既存2.2.0プロジェクトへの変更です。実装段階では本番公開・GitHubへの送信を行わず、口座や本人の実データへアクセスしていません。その後、本人の明示依頼により公開を進めます。実iPhone確認は未実施です。

## 更新を公開する前に

更新前のソースは `Pace-2.2.0-before-practical-update.zip` に保護し、同名JSONにSHA-256を記録しています。これは家計データのバックアップではありません。

1. ユーザーの更新前の暗号化バックアップを保存し、実ファイルを確認する。
2. 本更新のソースと検証報告を確認する。GitHub上の既存プロジェクトへ変更を反映する際、プロジェクトの親フォルダーやnode_modulesをアップロードしない。
3. `npm ci`、`npm test`、`npm run test:security`、`npm run test:experience`、`npm run build`、`npm run privacy:audit` を実行する。
4. **公開はユーザーが明示的に依頼した場合のみ行う。実装段階では行っていません。今回の公開作業は本人が明示的に依頼しています。**

## 端末での更新

入力を保存して閉じ、設定の更新確認または更新表示を使います。更新前にデータ形式と参照関係を確認し、バックアップの確認を促します。更新後は保管庫を解除し、残高・カード未払い・直近の支出を確認。「使い始める」「あとで」のどちらも選べます。新規インストールに移行案内は表示しません。

## DBとバックアップ

- Dexie version 3 → 4。既存ストアの定義と暗号化方式は維持し、expenseInboxストアだけ追加。古い金融レコードの暗号文を一括で書き換えない。
- バックアップschemaVersion 4。既存schema 1・2・3は検証して読み込める。新しい項目は任意項目。
- 起動時に暗号化データ・全テーブル・設定・形式・参照関係を、最初の書き込みより前に確認。初回だけ既存未分類支出にInboxの索引と準備済みの版を付ける。残高・金額・支払元・金融履歴は変えない。既存通知設定は個別設定済みとして扱い、時刻・頻度・ON/OFFを保持する。
- 設定が消えているのに記録が残っている状態は、新規扱いにして初期化しない。検証失敗なら保存・修復・削除を止め、読み取り専用の保護画面にする。
- Undoは既存暗号化draftsストアに変更した行だけを保持し、直近20件に制限。画像本体・鍵・金融認証情報は取り消し履歴へ複製しない。Undoはバックアップに入れず、復元時に削除する。
- 起動検証は保存済みの画像も一時的に復号して検査する。通常のホーム用データには画像を入れない。画像数が多い端末での起動時間は実機で追加確認が必要。

## 保存先の確認

暗号化バックアップは復号、schema、メタデータ、各テーブル、参照関係、内容の一致を実際に確認します。作成に成功してもOS側の実ファイルはブラウザから観察できないため「要確認」。本人が保存先の実物を確認した後の操作で「正常」になります。表示は確認日時時点のバックアップの状態で、以後の入力の自動バックアップを意味しません。CSV・Excelは復元用バックアップではありません。

## ロールバック

旧2.1.1や2.2.0にコードを戻すだけでは、新版のDBとschema 4を読めません。更新前のバックアップを必ず別途残してください。新版で入力した記録は新版のバックアップへ保存し、旧版へ全件戻るとは案内しないでください。金融データを維持する修正版を優先します。確認時は既存ブラウザのデータを消さず、別のブラウザ／端末と旧版が読める更新前バックアップを使います。

保護画面から保存する `pace-encrypted-recovery` は生の暗号化レコードを保護する別形式で、通常の復元画面では復元できません。暗号化データが壊れている場合、復旧できると保証しません。パスフレーズと以前の確認済みバックアップも維持します。

実機の使いながらの確認は [Pace 2.2.x iPhone実機確認手順](Pace%202.2.x%20iPhone実機確認手順.md) に記載しています。

バックアップを別の端末に復元した場合、元端末の「保存先確認済み」は引き継がず「要確認」にします。新しい端末で保存ファイルを確認してください。

## 更新保持検証の再現

`npm run test:preservation` は、比較用の2.2.0ビルドを別途必要とします。保護ZIPを検証専用の `../qa-baseline-2.2.0/pace` に展開して依存関係をインストール・ビルドするか、環境変数 `PACE_QA_PREVIOUS_DIST` に既存2.2.0のdistの絶対パスを指定します。実ユーザーのブラウザを使わず、架空データと使い捨てのブラウザだけで検証します。通常利用の前提条件ではありません。

公開版2.1.1から2.2.1への直接更新も、公開版と同じ83ソースファイルの旧ビルドを使い、架空データで金融記録の保持・オフライン起動・入力・Excel作成を確認しました。
