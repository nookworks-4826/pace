# Pace

**今使っていい金額を、いつでも。**

iPhoneやGalaxyで使う、端末内保存の家計管理PWAです。銀行口座と現金の残高から、カード未払い・固定費・返済予定・貯金予定を差し引き、ホームに「今使っていい金額」と「今日の目安」を表示します。手動管理はサーバーや金融機関との連携なしで使えます。任意の金融連携にはMoneytree LINKの正式な設定が必要です。

## できること

- 11ステップの初期設定。分からない項目は後回しにできます。
- 大きな金額入力、クイック入力、最近の店・金額、お気に入りから支出を登録。入力途中の下書きを保持します。
- 収入、複数カードと引落、借入と返済、固定費、貯金目標と移動、月予算・カテゴリー予算、残高調整を記録します。
- 履歴の検索・絞り込み・編集・削除。削除や支出保存の直後は「元に戻す」を利用できます。
- キーワード、過去の分類修正、類似文字列と端末内の軽量な学習によるカテゴリー候補。外部AIへ記録を送りません。
- 「これ、買ったら？」で購入後の使える金額を試算。支出を登録せずに確認できます。
- カテゴリー円グラフ、12か月の収支推移、日別推移、支出カレンダー、店別・支出額ランキング、記録が十分な場合の曜日傾向、週次比較、月別レポート。
- 支払日を過ぎても固定費を勝手に実績へ変更せず、支払済み・金額変更・今回はなしを自分で確認できます。
- JSON／暗号化バックアップ、CSV／Excel出力、カードCSVの列指定・プレビュー・重複候補確認。
- 明るいイエローのアイコン、4テーマ、ライト／ダーク／システム。6桁PIN、対応端末のデバイス認証、パスキー登録・解除。
- ホーム画面への追加、初回キャッシュ完了後のオフライン利用、操作して適用するPWA更新。
- 設定から更新を手動確認し、入力画面を閉じてから適用できます。別タブの更新でも入力中の画面を再読み込みしません。

## 2.1.0の設定画面

公開済みのアプリを更新する場合は、[2.1.0の更新手順](docs/UPDATING-2.1.md)を参照してください。

## Windowsで起動する

以前のv1.3.0では明るい配色、残高の内訳バー、短い操作アニメーション、購入前の試算、店名から学ぶ分類候補を追加しました。新規利用はライト表示が初期値です。既存の表示設定は保持し、設定の「テーマと表示」からライト表示へ切り替えられます。[変更内容と設計](docs/SUNNY.md)。

### 1. 必要なもの

1. [Node.js公式サイト](https://nodejs.org/en/download)から **Node.js 24 LTS** をインストールします。Windows用インストーラーにはnpmも含まれます。
2. [Git公式サイト](https://git-scm.com/downloads/win)からGit for Windowsをインストールします。
3. 公開する場合は[GitHub](https://github.com/)のアカウントを用意します。

インストール後はPowerShellを開き直し、確認します。

```powershell
node --version
npm --version
git --version
```

### 2. 開発用に起動する

このREADMEと`package.json`が置かれた`pace`フォルダーをPowerShellで開きます。パスに空白がある場合はダブルクォートで囲みます。

```powershell
cd "C:\作業フォルダー\pace"
npm install
npm run dev
```

表示されたLocal URL（通常は`http://localhost:5173/`）をWindowsのブラウザーで開きます。終了はPowerShellで`Ctrl+C`です。PowerShellが`npm.ps1`の実行を拒否する場合は、実行ポリシーを変えずに`npm.cmd install`、`npm.cmd run dev`を利用できます。

初回のパッケージ導入にはインターネット接続が必要です。通常利用の家計情報を外部へ送る処理はありません。

### 3. テストと本番ビルド

```powershell
npm run test
npm run typecheck
npm run build
npm run preview
```

`npm run build`で`dist`に公開用ファイルが生成されます。`preview`のURL（通常は`http://localhost:4173/`）では、本番用Service Workerも確認できます。`dist/index.html`をダブルクリックする`file://`起動は使いません。

開発サーバーでは通常Service Workerを動かしません。PWAとオフライン機能は本番ビルドをHTTPSまたはlocalhostで配信して確認します。iPhoneからWindowsのLAN内HTTPアドレスを開いた場合、画面確認はできてもWebAuthnやPWAの一部は動きません。日常利用はGitHub PagesのHTTPS URLを使ってください。

依存関係は`package.json`と`package-lock.json`で固定しています。再現性を優先するCIでは`npm ci`を使用します。

### 4. ブラウザー操作・画面幅・オフライン試験を再現する

初回だけ、同じアプリフォルダーでテスト用Chromiumを導入します。ブラウザー本体のダウンロードには通信が必要です。

```powershell
npx playwright install chromium
```

UI試験はアプリフォルダーのPowerShellから次を実行します。試験用サーバーを自動で起動・終了するため、開発サーバーを別に起動する必要はありません。

```powershell
npm run test:ui
```

オフライン試験にはPowerShellを2つ使います。ターミナル1で最新の本番ビルドを作り、プレビューを起動したままにします。すでに4173番で起動している場合は重複起動しません。

```powershell
npm run build
npm run preview -- --port 4173 --strictPort
```

ターミナル2もアプリフォルダーへ移動し、試験を実行します。

```powershell
$env:PACE_QA_BASE_URL = 'http://localhost:4173/'
npm run test:offline
Remove-Item Env:PACE_QA_BASE_URL
```

`test:ui`は専用サーバーに対し、記録・編集・削除・復元・PINの操作、375／390／430／768／1024pxの表示、仮想認証器でのWebAuthnを確認します。`test:offline`は本番プレビューのService Workerを準備してからブラウザー内の通信を切り、記録・再起動・各画面・Excel出力を確認します。Windows全体のネットワークを切断する必要はありません。

試験は通常利用のブラウザープロファイルと別の一時コンテキストで、架空のデータを使って実行します。結果やスクリーンショットは`test-results/`へ出力します。オフライン試験が終わったら、ターミナル1のプレビューを`Ctrl+C`で停止できます。オフライン試験で`ERR_CONNECTION_REFUSED`が出る場合は、プレビューが指定ポートで起動していることを確認してください。

Galaxy向けの仮想認証器テストを本番PWAのオフライン再起動まで含めて実行する場合は、4173番のプレビュー起動中に次を使います。端末全体の通信や普段のブラウザ設定は変更しません。

```powershell
$env:PACE_QA_BASE_URL = 'http://localhost:4173/'
$env:PACE_QA_OFFLINE = '1'
node scripts/qa-webauthn.mjs
Remove-Item Env:PACE_QA_BASE_URL, Env:PACE_QA_OFFLINE
```

HTMLがService Workerから読み込まれること、キャッシュにない同一配信元の試験用リクエストが遮断されること、本人確認を伴う署名検証で解除できることを確認します。これはGalaxy実機や認証プロバイダーのオフライン動作の保証ではありません。

## GitHub Pagesに公開する

初めて公開するときの手順です。**すでに公開済みのアプリを2.1.0へ更新する場合は、[更新手順](docs/UPDATING-2.1.md)を使ってください。** リポジトリや履歴を作り直す必要はありません。

1. GitHubで新しいリポジトリを作成します。無料アカウントでPagesを使う場合は公開リポジトリが利用できます。
2. **`outputs/pace`の中身をリポジトリのルート**に置きます。ルート直下に`package.json`、`src`、`public`、`.github/workflows/deploy.yml`が必要です。`.github`をコピーし忘れないでください。
3. GitHubのリポジトリ画面で、**Settings → Pages → Build and deployment → Source → GitHub Actions**を選びます。用意済みワークフローを使うので、別のテンプレートを追加する必要はありません。[GitHub公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
4. 新規の空リポジトリに初めて送る場合だけ、ローカルのアプリフォルダーで次を実行します。URLは自分のものへ変更してください。Gitの作者名・メールは、公開してよい表示名とGitHubのnoreplyアドレスを事前に設定します。

```powershell
git init
git branch -M main
git add .
git commit -m "Add Pace PWA"
git remote add origin https://github.com/YOUR_NAME/YOUR_REPOSITORY.git
git push -u origin main
```

5. GitHubのActionsで **Test and deploy Pace** が完了すると、Pagesの公開URLが表示されます。通常は`https://YOUR_NAME.github.io/YOUR_REPOSITORY/`です。

以降、`main`へのpushで`npm ci → テスト → ビルド → Pages公開`が実行されます。テストやビルドが失敗した場合、公開ジョブは実行されません。Actionsから手動実行もできます。

Viteの`base`は`./`、ルーティングは`HashRouter`です。リポジトリ配下の公開や、`#/history`などの画面での再読み込みに対応します。必要な場合だけ環境変数`VITE_BASE_PATH`で配信パスを変更します。

GitHubへ保存するのはアプリコードです。バックアップ、CSV、Excel、実データ入りスクリーンショットをリポジトリに置かないでください。一般的な出力拡張子は`.gitignore`でも除外していますが、任意に名前を変更したファイルまで自動で守れるわけではありません。

## iPhoneのホーム画面に追加する

1. Safariで公開したPaceのHTTPS URLを開きます。
2. 共有メニューを開きます。
3. 「ホーム画面に追加」を選びます。
4. 「追加」を押します。iOSで「Webアプリとして開く」が表示される場合はオンにします。
5. ホーム画面のPaceアイコンから起動します。

Safariのメニュー構成はiOSにより少し異なります。[Appleの案内](https://support.apple.com/guide/iphone/bookmark-a-website-iph42ab2f3a7/ios)

最初は通信できる状態で開き、画面の読み込みとService Workerのキャッシュを完了させてください。その後はオフラインでも支出・収入・履歴・分析・カード・借入・貯金・設定・バックアップを使えます。キャッシュやブラウザーデータを消した後の初回起動には、再び通信が必要です。

更新を検出すると「Paceの更新があります」が表示されます。「更新する」を押したときに適用します。勝手にリロードせず、更新処理でIndexedDBは削除しません。編集中の内容は先に保存してください。

v1.1.1以降は **設定 → アプリの更新 → 更新を確認** からも確認できます。新しい版をダウンロードし終えると「更新を適用」になります。「後で」にした更新も設定から適用できます。入力・設定画面を開いている間は、閉じてから更新するよう案内します。オフライン中も記録を続けられ、更新の確認は通信復帰後にできます。

## パスキーで解除する（v1.2.0以降）

**設定 → アプリロック → パスキー → パスキーを登録** で設定します。以前のロックがある場合は先に「現在のロックで確認」を押します。登録後は「認証を試す」で確認できます。Galaxyの指紋やiPhoneのFace ID・Touch IDなど、端末が提示する方法で本人確認します。家計データは端末内のままです。v1.2.1では説明を「ヘルプ」にまとめ、通常は操作ボタンを中心に表示します。詳しくは[パスキーの設定手順](docs/PASSKEYS.md)を参照してください。

## Galaxyのホーム画面と指紋認証

1. Galaxyの「設定」で「指紋」を検索し、端末の画面ロックと指紋を登録します。設定画面の名称はOne UIや機種により異なります。
2. ChromeまたはWebAuthnに対応したSamsung Internetで、公開したPaceの**HTTPS URL**を開きます。WindowsのLAN内HTTPアドレスではデバイス認証を設定できません。
3. Chromeのメニューから「ホーム画面に追加」または「アプリをインストール」を選びます。ブラウザにより表示名は異なります。
4. Paceの **設定 → アプリロック → デバイス認証 → デバイス認証を設定** を選びます。指紋など、端末の案内に従って確認します。
5. 「認証を試す」で実際に認証できることを確認します。その後、アプリを閉じて開き直した場合も解除できることを確認してください。

指紋が利用できる環境では端末の認証画面で指紋を使えます。WebAuthnの`platform`と`userVerification: required`を使い、本人確認を必須にしています。ただし、**Webアプリから指紋だけに限定することはできません**。端末のPIN・パターン等が提示される場合もあります。Paceの6桁PINと、端末の画面ロック用PINは別のものです。[Google公式：端末での本人確認](https://support.google.com/chrome/answer/14124480?hl=ja)

対応状況は端末名から決め打ちせず、ブラウザのAPIで確認します。HTTPSでない、APIがない、利用できる端末認証が見つからない、確認に失敗した場合を分けて表示します。設定を変更してPaceに戻ると再確認し、「もう一度確認」でも更新できます。利用できない環境では「6桁PIN」を設定してください。**すでにデバイス認証でロックしている場合、未設定のPINで迂回することはできません。**

ChromeとSamsung Internetでは家計データの保存領域が別です。普段利用するブラウザでセットアップし、ブラウザ変更時はバックアップを復元してロックを登録し直してください。生体情報や指紋画像をPaceが取得・保存することはありません。認証情報の保存・同期はOSや認証プロバイダーの設定に従いますが、家計情報の同期はしません。[Google公式：AndroidとChromeの対応環境](https://developers.google.com/identity/passkeys/supported-environments)

Galaxy実機、実際のSamsung Internet、指紋センサー、OSの認証画面はこの開発環境では未検証です。Androidの画面サイズ・ユーザーエージェントと仮想認証器での試験は、実機の指紋認証の保証ではありません。利用端末で登録・解除・キャンセル後の再試行・オフライン再起動を確認してください。

## 最初に入力する情報

| 項目 | 入力する内容 |
| --- | --- |
| 現在の銀行＋現金残高 | すぐ使える口座と現金の合計。別に確保した貯金は除きます。 |
| 現在のカード未払い | このアプリでまだ個別記録していない利用分。カードごとに入力します。 |
| 親などへの借入残高 | 元の借入額、記録開始時の残高、毎月の返済予定、返済日。概算ならその表示を付けます。 |
| 給料日 | 毎月の日付。予想給与は分かる場合だけ入力します。 |
| 任意の項目 | 月予算、固定費・サブスク、貯金目標と毎月の予定。 |

分からない金額を仮定する必要はありません。残高未設定では「現在残高を入力すると計算できます」と表示します。カードや借入などを後回しにした場合、表示金額は**入力済みの情報だけ**から計算されます。実際に負担がある項目の入力が揃うまでは、完全な見通しにはなりません。

既存の借金は「今回、現金を受け取る借入」をオフにします。今入力した口座残高に借入金が含まれている場合もオフです。このチェックは新たに受け取る資金を残高へ加えるためのものです。

## 毎日の使い方

ホームを開き、「今使っていい金額」と「今日の目安」を確認します。メインの金額をタップすると、どの予定をいくら差し引いたか確認できます。表示が違うと感じたら「この金額が違う？」から残高や未払いを見直します。

下の中央の「＋」から、金額、店名、支払方法を入れます。たとえば`サイゼリヤ 1280`、`スタバ 680 クレカ`をクイック入力すると入力欄へ反映されます。候補を確認して「記録する」を押します。お気に入りも確認画面を経由します。

カードは**購入日に支出登録**し、後日の引落はカード画面の「引落を記録」から登録します。同じ引落を普通の支出として登録しないでください。借金返済と貯金への移動もそれぞれ専用画面を使います。

固定費が発生したら「支払った・金額変更」から実際の金額を登録します。「今回はなし」でその回だけ確保を解除します。確認を後回しにすると確保額は残ります。支出がない日は「今日は使っていない」を選べます。

## 金額の計算

計算は`src/domain/finance.ts`の純粋関数へ分離しています。取引履歴から再計算し、画面上の集計値だけを書き換える方式にはしていません。円は整数、日付は日本時間の暦日で扱います。未来の日付の実績は当日の残高・実績集計に含めません。

### 持っているお金と使っていいお金

```text
liquidBalance（現在使える資金）
  = 開始残高 + 確定収入 + 現金を受け取る借入 + 残高調整の差額
    − 現金・デビット・銀行・その他払いの支出
    − カード請求支払い − 借金返済 − 実際の貯金移動

creditCardOutstanding（カード未払い）
  = 各カードの max(0, 初期未払い + 記録した利用額 − 記録した支払額) の合計

safeToSpend（今使っていい金額）
  = liquidBalance − creditCardOutstanding − upcomingFixedCosts
    − remainingDebtPaymentReserve − remainingSavingsReserve
```

`safeToSpend`が負でも内部では保持し、メイン表示は0円と不足額に分けます。実際のカード支払超過が履歴修正で生じた場合は、カード画面に「支払超過」を別表示します。使える現金として加算しません。

| 操作 | 持っているお金 | カード未払い | 今使っていい金額 |
| --- | ---: | ---: | ---: |
| 最初 | 30,000円 | 0円 | 30,000円 |
| カードで5,000円購入 | 30,000円 | 5,000円 | 25,000円 |
| 後日5,000円引落 | 25,000円 | 0円 | 25,000円 |

カード利用は購入日に月間支出へ反映し、引落を支出合計に二重計上しません。

### 固定費・返済・貯金の確保

- **固定費**：開始日以降、今月末までに支払日がある未確認分を確保します。月をまたいだ未確認分も持ち越します。年払いは開始日の月に発生し、31日などがない月は月末に丸めます。支払いに対応したExpenseまたは「今回はなし」がある回は除きます。固定費を終了すると、未確認分の確保も終了し、記録済み実績は残ります。
- **借金返済**：`min(借金残高, max(0, 毎月の返済予定 − 今月の返済実績))`を確保します。返済予定日が来月以降の場合は今月分を確保しません。5,000円の予定に対して2,000円を返したら残り3,000円です。借金残高は開始時残高から返済履歴を引きます。
- **貯金**：`min(目標までの残額, max(0, 毎月の貯金予定 − 今月の移動実績))`を確保します。予定5,000円のうち2,000円移動済みなら残り3,000円です。既にある貯金の開始額は、使える銀行・現金の開始残高に含めません。

予約していた5,000円を実際に払うと、使える資金が5,000円減る一方、対応する確保額も5,000円減ります。そのため同じ予定で`safeToSpend`が二重に減ることはありません。実際の金額を変更した場合は、その差分が反映されます。

確保の基準はカレンダー月では月末、給与周期では今期末です。未確認の固定費も含みます。将来の予想給与は、実際の入金を記録するまで残高に加えません。新規の借金は返済開始を初期OFFにし、残高だけ表示できます。旧記録の確保設定は維持します。

### カレンダー月の既存計算と給与周期の目安

```text
monthlyBudgetRemaining = 月予算 − 購入日ベースの今月の生活支出
dailyAvailableBase = 予算あり ? min(safeToSpend, monthlyBudgetRemaining) : safeToSpend
dailyAllowance = round(max(0, dailyAvailableBase) ÷ 今日を含む月末までの日数)
今日のあと = max(0, dailyAllowance − 今日の支出)

budgetProgress = 今月の生活支出 ÷ 月予算
timeProgress = 今月の経過日数 ÷ 今月の日数
paceRatio = budgetProgress ÷ timeProgress
```

ペース比が1以下なら「予定ペース」、1超〜1.25未満は「少し早め」、1.25以上は「ペース注意」です。0円の予算も設定でき、その場合の今日の目安は0円です。予算未設定では予算による制限をかけません。

以下は口座管理を有効にする前のカレンダー月の既存挙動です。**今日の目安はその時点の残額から毎回計算します。** 支出を登録すると目安自体も変わり、さらに「今日のあと」では当日の支出を引きます。朝の金額を固定して減らす方式ではありません。これは指定の計算式に合わせた挙動です。「今日のあと」は負にならない目安表示で、超過の有無は今日の支出と目安の数字・進捗で確認できます。

給与周期では、今日の通常支出を現在の残額へ一度だけ戻して朝の計算枠を求め、今日を含む今期末までの日数で割って切り捨てます。予算があれば同じ期間の予算残額で制限します。「今日はあと」はその目安から今日の通常支出を一度だけ引きます。明日の目安は今日を目安内に収める条件で再計算し、今期最終日は次の給与を仮定せず「—」と表示します。固定費は別の確保額なので今日の通常支出に含めません。

### 残高を合わせる・過去の履歴を追加する

設定の「残高を合わせる」に、**いま実際にある銀行＋現金の合計**を入力します。差額はBalanceAdjustmentとして履歴に残ります。最初に残高入力を飛ばしてから取引を記録した場合も、`reconcileLiquidBalance`が既存履歴を考慮して現在残高を合わせます。

初期未払いは「個別の支出としてまだ記録していない利用分」です。初期未払いに含めた購入を後からカードCSVで取り込むと、その分は二重になります。取り込む前に初期未払いを対応分だけ見直してください。開始前の現金支出・収入を追加した場合も現在残高へ影響するため、取り込み・修正後に実残高と照合します。重複候補表示は補助で、全重複を自動判定するものではありません。

カードの次回支払額は締め日と翌月／翌々月の設定から求める**概算**です。休日移動、加盟店からの到着遅れ、初期未払いの請求月、カード会社独自の締め処理には対応しません。実際の明細を確認して引落を記録してください。

## 保存・バックアップ・iPadへの移行

家計記録は端末内の暗号化したIndexedDBに保存します。広告SDK・解析ツール・外部AIへの送信はありません。金融連携を有効にした場合だけ、許可したMoneytreeの公式エンドポイントから口座・残高・明細を取得します。銀行ID・パスワードをPaceへ保存しません。Service WorkerはアプリとOCRモデルの静的ファイルだけをキャッシュし、家計データ・画像・トークンをGitHubやCache APIへ保存しません。アプリコードの取得と更新時には配信元への通信が発生します。

**端末内保存のため、ブラウザデータ削除で失われる可能性があります。** 端末の故障・機種変更・OSによる保存領域の整理にも備え、定期的にバックアップしてください。URLや利用ブラウザーが変わると、別の保存領域になる場合があります。

設定 → バックアップと書き出しから、形式を選んでファイルを作成し、「ファイルを保存」を押します。iPhoneでファイルが開いた場合は共有メニューから「ファイルに保存」を選び、保存先にあることを確認してください。

| 形式 | 用途 |
| --- | --- |
| JSONバックアップ | 保存済みの全家計記録・設定・カテゴリー・学習ルールを復元するためのファイル。内容は平文です。未保存の入力下書きは含みません。 |
| `.pacebackup` | パスワードで暗号化した復元用ファイル。AES-256-GCM、PBKDF2-SHA-256・600,000回（旧310,000回ファイルも読込可能）、毎回ランダムなsaltとIVを使用します。 |
| CSV | UTF-8 BOM付きの取引一覧。Excel等で確認できます。完全復元用ではありません。 |
| Excel | 概要・支出・収入・カード・借金・固定費・月別集計・カテゴリー別集計・口座・振替・外部明細・口座調整の12シート。完全復元用ではありません。 |

暗号化パスワードは保存しません。忘れた場合は復号できません。PINとバックアップ用パスワードは別の設定です。CSVでは店名やメモが表計算の数式として実行されないよう保護します。

復元は設定 → バックアップを復元でファイルを選び、必要ならパスワードを入力します。読み込み検証と確認を経て、**その端末の全家計データを置き換えます。結合ではありません。** 形式、バージョン、金額、ID、記録間の関連付けを検証し、全テーブルの置き換えは1つのIndexedDBトランザクションで行います。失敗時は元のデータを保ちます。復元前のバックアップも取ってください。

iPhoneを主端末として、iPadへ移す場合は次の順です。

1. iPhoneでJSONまたは暗号化バックアップを保存。
2. AirDropや「ファイル」など、自分で選んだ方法で移動。
3. iPad側でPaceを開き、バックアップを復元。

自動同期やiCloud同期は実装していません。両方の端末で入力した内容を自動結合もしません。移行先のアプリロックは端末ごとに設定します。生体認証情報・PIN設定は家計バックアップへ含めません。

## アプリロック

設定から「パスキー」「デバイス認証」「6桁PIN」「ロックなし」を選びます。パスキーは保存可能な認証情報（resident key）を必須にして登録します。デバイス認証にはHTTPSと対応するplatform authenticatorが必要です。WebAuthnの`userVerification: required`を指定し、challenge、origin、RP ID、本人確認フラグ、署名を端末内で検証します。Galaxyの指紋認証、iPhoneのFace ID・Touch ID、端末の画面ロックなどが使われます。**特定の認証方法を必ず利用できるという保証はありません。** 利用できない環境ではPINを選べます。

PINは平文保存せず、ランダムsalt付きPBKDF2-SHA-256のハッシュを保存します。連続失敗時は待ち時間を設けます。再認証間隔は「すぐ・1分・5分・15分」で、起動し直したときは認証が必要です。

PIN・パスキーは画面の認証です。2.0では別に、パスフレーズでIndexedDB全体を暗号化する保管庫を追加しました。保管庫の鍵はメモリにだけ置き、保管庫ロック・再起動後はパスフレーズで開きます。パスキーだけで暗号化データを復号する方式ではありません。パスフレーズを失うと復号できないため、本人が使える暗号化バックアップを保存してください。詳しくは[暗号化の構成](docs/PRIVACY-AND-ENCRYPTION.md)を参照してください。

WebAuthnの認証情報がOSの設定によって同期される場合がありますが、Paceが家計情報をそのサービスへ送信することはありません。実機でのGalaxy指紋／Face ID／Touch ID認証はこの開発環境では未確認です。

## Known limitations

- Moneytreeの正式契約・Public Client登録・CORS確認・本番端末検証が未完了のため、現在の配布設定では銀行やカードの自動取得は無効です。mockは試験専用で、通常の台帳へ自動投入しません。
- PayPayの個人ウォレット、Apple WalletのSuicaへPaceから直接チャージするAPIは利用できません。公式アプリで操作し、Paceでは振替と残高を確認します。
- 分割・リボ・利息・休日によるカード引落日の移動は自動計算しません。実際の請求を確認し、締め日・支払日・カード商品を設定してください。
- 給与の将来額、未取得の残高、Moneytreeが提供しない未確定状態を推測しません。未知の支払元や旧合計残高の分割が済むまでsafeToSpendは未確認になります。
- 閉じたiOS PWAを端末内タイマーだけで指定時刻に起動・同期・通知することはできません。現在は一般文面のカレンダー通知かアプリを開いている間の通知を使います。Push送信サーバー・購読は用意していません。
- OCRは精度を保証せず、必ず確認します。初回は同一配信元からモデルを取得し、その後キャッシュ済みならオフラインで読めます。未対応の写真形式や時間切れでは手入力できます。
- 複数端末の家計データ自動同期・競合解決はありません。iPhoneとiPadの間は本人がバックアップで全置換して移行します。復元後は金融連携を再認可します。
- 全台帳を一貫したスナップショットとして読んで集計します。数十万件の性能保証、完全な集計キャッシュは未実装です。
- 公開中のアプリはGitHubへ更新ファイルを反映し、Actionsの成功後に更新されます。手元のビルドだけでは変わりません。実機のiPhone・Galaxyのキーボード、Face ID・指紋、オフライン再起動は利用端末での確認が必要です。
